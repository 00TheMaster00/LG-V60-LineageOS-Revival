# Repository Provenance and Official Ownership

## Canonical project

The official repository is:

<https://github.com/00TheMaster00/LG-V60-LineageOS-Revival>

The canonical maintainer and credit target is
[@00TheMaster00](https://github.com/00TheMaster00).

## Why older commits say `The1-Master`

The project was initially created and published from the maintainer's earlier
`The1-Master` GitHub account. The repository was transferred to
`00TheMaster00` on 2026-08-14. Git preserves the author and committer metadata
already stored inside old commits, and exported kernel/research patches also
retain their historical headers. That is expected provenance, not evidence
that the repository was copied or stolen.

New commits, documentation credit, repository links and release ownership
should use `00TheMaster00`. The old identity is retained only where rewriting
it would falsify or obscure the historical record.

## How to identify an official release

1. Start from the canonical repository URL above.
2. Confirm the release or tag is owned by `00TheMaster00`.
3. Compare every downloaded artifact with its published SHA-256.
4. Check that the release commit is reachable from the canonical repository.
5. Treat mirrors, forks, chat uploads and rehosted APKs as unofficial unless
   the canonical repository links to them explicitly.

Forks are allowed by the repository license for the original project files,
but they must preserve upstream/community credits and may not imply that
`00TheMaster00`, LG, Qualcomm, LineageOS, XDA or the cited contributors tested
or endorsed the fork.

## Maintainer boundary

Only `00TheMaster00` is listed as the canonical maintainer. A GitHub App,
automation token or collaborator permission may technically be able to write
to the repository, but that access is an implementation detail—not a transfer
of authorship or ownership. Changes should enter through reviewable commits or
pull requests and pass the public-release validation workflow.
